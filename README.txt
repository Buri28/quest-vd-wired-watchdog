========================================================================
 Quest VD Wired Watchdog
========================================================================

Quest 3 の有線接続 (Quest VD Wired) が切れたときに、自動で復旧させる
常駐スクリプトです。

Quest VD Wired 単体では、HMD の電源を切って入れ直すと接続が戻らず、
毎回タスクトレイから「Diagnose and fix」を手で押す必要があります。
このスクリプトはその手間をなくします。

※ これは非公式のコンパニオンツールです。Quest VD Wired 本体、gnirehtet、
   Meta、Virtual Desktop のいずれとも関係ありません。


------------------------------------------------------------------------
 できること
------------------------------------------------------------------------

  HMD の電源 OFF → ON ........... 自動で再接続
  HMD のスリープ → 復帰 ......... 自動で再接続
  ケーブルの抜き差し・接触不良 .. 復帰を検知して自動で再接続
  ケーブルが抜けている間 ........ 何もせず待機 (無駄な再起動をしない)

タスクトレイのアイコンで、常駐状態と接続状態がひと目で分かります。


------------------------------------------------------------------------
 必要なもの
------------------------------------------------------------------------

  ・Windows 10 / 11
  ・Quest VD Wired (別途インストールしてください)
      https://github.com/kkoemets/quest-vd-wired
  ・Meta Quest 3 (開発者モード・USB デバッグ有効)
  ・USB 3 のデータケーブル

Windows 標準の PowerShell 5.1 で動作します。追加のインストールは不要です。


------------------------------------------------------------------------
 導入
------------------------------------------------------------------------

  1. Quest VD Wired をセットアップし、手動で一度は接続できることを
     確認してください

  2. ZIP を右クリック → プロパティ → 「ブロックの解除」にチェック → OK
     (展開する前に行ってください。ダウンロードしたファイルは Windows に
      ブロックされ、警告が出ることがあります)

  3. Quest VD Wired のフォルダの中に、quest-vd-wired-watchdog フォルダ
     ごと展開します

       quest-vd-wired-v4.1.4-windows-x64\   ← Quest VD Wired のフォルダ
       ├─ quest-vd-wired.exe
       └─ quest-vd-wired-watchdog\          ← ここに展開する
          ├─ install.cmd
          ├─ uninstall.cmd
          ├─ run_debug.cmd
          ├─ watchdog.ps1
          ├─ README.txt
          ├─ README_EN.txt
          └─ LICENSE.txt

  4. quest-vd-wired-watchdog フォルダを開き、install.cmd をダブルクリック

Quest VD Wired を別の場所にインストールしている場合は自動検出に失敗します。
その場合は watchdog.config.json の questVdWiredPath に実際のパスを
記入してください (下記「設定」を参照)。

これだけです。実行すると次の 3 つが同時に行われます。

  ・adb.exe と quest-vd-wired.exe のパスを自動検出し、
    watchdog.config.json を生成
  ・Windows のスタートアップに登録 (次回ログオンから自動起動)
  ・その場で常駐を開始

タスクトレイに丸いアイコンが表示されれば成功です。


------------------------------------------------------------------------
 同梱ファイル
------------------------------------------------------------------------

  install.cmd .......... 常駐開始 ＋ 自動起動の登録
                         導入時に一度だけ実行します

  uninstall.cmd ........ 常駐停止 ＋ 自動起動の登録解除
                         使うのをやめるときだけ実行します

  run_debug.cmd ........ 前景で実行してログを見る
                         自動起動の登録はしません。不具合調査用

  watchdog.ps1 ......... 本体

  README.txt ........... このファイル
  README_EN.txt ........ 英語版
  LICENSE.txt .......... ライセンス

  watchdog.config.json は初回実行時に自動生成されます
  (配布物には含まれていません)


------------------------------------------------------------------------
 タスクトレイ
------------------------------------------------------------------------

時計の横に丸いアイコンが表示されます。見当たらない場合は「^」を押して、
表示領域にドラッグして固定してください。

  緑 ... 接続中
  灰 ... 未接続 (Quest が見えていない)
  赤 ... 切断を検知・復旧作業中

マウスを乗せると詳細が表示されます。右クリックで次の操作ができます。

  ・ログを開く
  ・設定ファイルを開く
  ・今すぐ再接続  ... 待たずに手動で復旧処理を実行
  ・終了          ... 常駐を停止 (自動起動の登録は残ります)


------------------------------------------------------------------------
 設定
------------------------------------------------------------------------

watchdog.config.json を編集してください。
編集後はトレイアイコンを右クリック →「終了」してから install.cmd を
実行し直すと反映されます。

  adbPath            自動検出   adb.exe のパス
  questVdWiredPath   自動検出   quest-vd-wired.exe のパス
  logPath            (下記)     ログの出力先
  intervalSec        10         監視間隔 (秒)
  failThreshold      3          連続何回異常を見たら再起動するか
  settleSec          60         再起動後、復帰を待つ上限 (秒)
  settlePollSec      5          復帰待ち中の確認間隔 (秒)
  cmdTimeoutSec      10         adb コマンドの打ち切り時間 (秒)
  maxRestarts        3          連続何回まで再起動を試みるか
  giveUpWaitSec      600        上限に達したあとの待機時間 (秒)

  logPath の既定値: %LOCALAPPDATA%\GnirehtetVD\watchdog.log


 ● failThreshold を下げないでください

   USB の接触が不安定な環境では、接続が数十秒おきに一瞬途切れることが
   あります。3 は、そうした一過性のフラつきで再起動が走らないようにする
   ための値です。1 にすると、正常な使用中に何度もアプリが再起動され、
   かえって使えなくなります。


------------------------------------------------------------------------
 仕組み
------------------------------------------------------------------------

リンクが生きているかを、次の 3 条件がすべて揃っているかで判定します。

  1. Quest 側に tun インターフェースがある
  2. PC 側で quest-vd-wired.exe が動いている
  3. adb reverse のマッピングが張られている

  ・デバイスが adb devices に見えない
      → ケーブルか電源の問題。何もせず待機

  ・デバイスは見えるが、上の 3 条件のどれかが欠けている
      → quest-vd-wired.exe を起動し直す

ただし、PC 側か Quest 側のアプリがそもそも起動していない場合は、3 回連続を
待たずに即座に再起動します。「アプリが動いていない」は接触不良のような
一過性の現象ではなく確定的な異常だからです。PC を再起動した直後、HMD の
電源を入れ直した直後がこれに当たり、いずれも数秒で復旧します。

tun の有無だけでは不十分です。HMD を起動したまま PC を再起動すると、
Quest 側の VPN は生き残るため tun は残りますが、PC 側にはホストプロセスも
adb reverse マッピングも存在しません。この「殻だけが残った状態」を
健全と誤判定しないよう、PC 側の 2 条件も必ず確認しています。


------------------------------------------------------------------------
 トラブルシューティング
------------------------------------------------------------------------

■ トレイアイコンが出ない

  run_debug.cmd を実行してエラーを確認してください。
  adb.exe または quest-vd-wired.exe のパスが自動検出できていない場合は、
  watchdog.config.json に直接記入してください。

■ 何度も再接続を繰り返す

  Quest VD Wired 側が復旧できない状態です。3 回失敗すると 10 分間
  待機に入ります。トレイアイコンが赤のままなら、Quest VD Wired 本体の
  トレイメニューから「Diagnose and fix」を実行してください。

■ 動いているか分からない

  トレイアイコンを右クリック →「ログを開く」で動作履歴を確認できます。
  状態が変わったときだけ記録されるため、接続が安定している間は
  行が増えません。

■ スクリプトがエラーで起動しない

  watchdog.ps1 を編集した場合、BOM 付き UTF-8 で保存してください。
  BOM が失われると Windows PowerShell 5.1 が文字コードを誤認し、
  無関係な行で構文エラーになります。


------------------------------------------------------------------------
 開発者向けメモ
------------------------------------------------------------------------

以下は実測で確認した、やってはいけない操作です。
同種のツールを作る場合の参考に。

■ quest-vd-wired.exe をサブコマンド付きで実行しない

  常駐中に status / repair / start / stop を叩くと、動作中のセッションを
  巻き込んで停止します。死活監視に status を使うことはできません。

■ adb kill-server を実行しない

  adb reverse のマッピングは adb サーバー内に保持されているため、
  サーバーを再起動するとリンクが壊れます。

■ ping で疎通確認をしない

  gnirehtet は ICMP を中継しないため、正常に接続されていても ping は
  100% ロスします。死活判定には使えません。
  tun インターフェースの有無を見てください。
